# Облік: редагування записів (іконка «олівець») — план

Запит власника (24.10.2026): у вже зроблених транзакціях має бути іконка редагування, щоб виправити запис,
а не видаляти й додавати заново. Позначка [x] — зроблено й викладено.

## Як зараз

- **Кабінет → Облік → Історія** (`src/pages/cabinet/LedgerPage.tsx`): у рядку лише «Видалити» (з підтвердженням,
  переказ — обома половинами). Змінити запис не можна.
- **Плашка Alt+Q → Історія** (`History` у `src/desktop/Bar.tsx`): лише перегляд.
- **ШІ-помічник уже вміє правити** (`editTx` у `desktop/src/main.cjs`) — з правилами: переказ змінюється обома
  половинами (лише сума й нотатка), у запису угоди не можна міняти суму й тип. Ці правила й беремо за основу.
- **База дозволяє**: політика «облік персонажа» (`0001_init.sql`) — `for all` для власника, тож `update` уже працює.
  Обмеження: `amount > 0`, категорія ≤ 30 символів, нотатка ≤ 200, рахунок `cash` / `card`. **Міграція не потрібна.**
- Кабінет на сайті — лише перегляд (`canEdit` у `src/lib/app.ts`, клас `.edit-only` ховає кнопки), правити можна
  в програмі. Олівець — так само `edit-only`.

## Що можна змінювати — за джерелом запису

| Джерело (`source`) | Тип | Сума | Категорія | Рахунок | Нотатка |
|---|---|---|---|---|---|
| кабінет, Alt+Q, імпорт, звірка | так | так | так | так | так |
| переказ (`transfer`) | — | так, обидві половини | — | — (напрям — видалити й зробити новий) | так, обидві |
| угода (`deal`) | — | — (рахується з угоди) | так | так | так |

Дата й час не змінюються ніде.

У запису угоди замість полів суми й типу — підказка «Суму змінює угода: видали її в «Угодах» і запиши знову».

## Кроки

- [x] **Правила в одному місці.** `src/lib/txEdit.ts`: `txPatch(row, form) → { set } | { error }` — що з форми
  можна записати для цього `source` (таблиця вище) і чи пройде обмеження бази. Тести `txEdit.test.ts`:
  кожне джерело, сума ≤ 0, задовга нотатка, переказ.
  `editTx` у `main.cjs` (ШІ) лишається, але правила тримати однаковими — як `quick.cjs` дзеркалить `cats.ts`.
- [x] **Іконка.** У `src/components/Icon.tsx` немає олівця — додати `edit` (той самий стиль: 24×24, обвідка 2 px).
- [x] **Кабінет → Історія.** У рядку — кнопка-іконка «Редагувати» (`title`, `aria-label`) поруч із «Видалити»,
  `edit-only`. Натискання розгортає рядок у форму на місці (без модального вікна й без стрибка списку):
  ті самі поля, що в «Додати запис» (тип, сума, категорія, рахунок, нотатка).
  Кнопки «Зберегти» / «Скасувати»; Enter — зберегти, Esc — скасувати. Відкрита одна форма за раз.
- [x] **Збереження.** Звичайний запис — `update … eq('id')`; переказ — обидві половини (`source = 'transfer'`
  і той самий `ts`, як у видаленні). Після — `reload()`;
  баланси, підсумки й графік перераховуються самі (рахуються з рядків). Помилка — текстом у рядку, форма лишається.
- [x] **Alt+Q → Історія** (другим етапом): олівець у правій панелі відкриває ту саму форму в плашці
  (через міст `preload.cjs` → `editTx` у `main.cjs`, вже з перевіркою власника).
- [x] **Перевірка в програмі:** змінити суму ручного запису → змінився баланс і підсумок дня; переказ → обидві
  половини; запис угоди → суму змінити не дає; на сайті (не в програмі) олівця немає.

## Рішення власника (25.10.2026)

1. Дату й час **не** змінюємо.
2. Редагування самих угод (кількість, ціна) — **не** потрібне.
3. Історію змін **не** зберігаємо.

Оцінка: правила + кабінет — пів дня; плашка Alt+Q — ще 1–2 години.
