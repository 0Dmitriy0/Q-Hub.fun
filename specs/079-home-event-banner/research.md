# Research: Банер івенту на головній

## R1. Чому картка блимає

- **Decision**: `HalloweenBanner` не повертає картку, поки `info === null` (дані не прийшли), — хіба що підказка з минулого візиту каже «івент був» (R3).
- **Rationale**: зараз рядок `if (info && (info.ended || …)) return null` пропускає стан `info === null`, і компонент малює текст «Карта привидів уже тут» до відповіді бази. Це навмисне рішення часів івенту («без стрибка»), але після кінця івенту воно дає «з'явилась — зникла» на кожному візиті.
- **Alternatives considered**: (а) показувати каркас-заглушку того ж розміру — права колонка лишилась би порожньою без івенту, суперечить FR-002; (б) брати стан івенту з даних збірки (знімок, як ціни в `public/snapshot`) — точніше для першого візиту, але дані застарівають до наступного деплою, а івент вмикає адмін у базі; можна додати пізніше, якщо SC-004 не влаштує.

## R2. Ширина тексту без картки

- **Decision**: `.h-hero` за замовчуванням — одна колонка; дві колонки (`1.5fr / 1fr`) — лише `.h-hero:has(> .h-promo)`. Медіазапит `max-width: 1000px` лишається (одна колонка, картка під текстом).
- **Rationale**: розмітка вже правильна — картка є дитиною `.h-hero` лише тоді, коли її малюють; CSS сам вибирає розкладку, не треба передавати стан з компонента в `Home.tsx`. `:has` підтримують усі сучасні браузери; у старих — одна колонка завжди, що безпечно (картка просто під текстом, як на телефоні).
- **Alternatives considered**: підняти стан у `Home.tsx` і ставити клас — більше коду й зв'язку між компонентами без вигоди.
- **Опис (`.h-lead`)** зараз обмежено `62ch` для читабельності. На всю ширину без картки рядок у 62 знаки виглядає вузьким біля широкого заголовка — у одноколонковому режимі підняти межу до ~80ch; заголовок, промокод і кнопки — на всю ширину.

## R3. Підказка для повторних візитів (FR-005)

- **Decision**: `localStorage['qhub-hero-event']` = `'halloween'` або відсутній. Читається синхронно при першому рендері: є — картка малюється одразу (у вигляді «привиди»/збереженого типу), далі уточнюється даними. Прийшли дані «івенту немає» — ключ видаляється, картка зникає (один раз — edge case «скінчився між візитами»). Прийшли «івент є» — ключ записується з типом (`ghosts` / `pumpkins` / `both`), щоб і текст не змінювався.
- **Rationale**: SC-003 (без стрибка під час івенту) без серверного стану на першому кадрі; помилки сховища (приватний режим) — `try/catch`, поведінка як на першому візиті.
- **Alternatives considered**: `sessionStorage` — не працює між візитами; cookie — зайве для сервера.

## R4. Тестована логіка

- **Decision**: `src/lib/halloween.ts` — `heroBanner(info | null, hint | null)` → `null` (не показувати) або `{ show: 'pryvydy' | 'harbuzy' | 'pryvydy,harbuzy', kind: 'ghosts' | 'pumpkins' | 'both' }`; `bannerHint(info)` → що записати в підказку (або видалити). Тести `vitest`: немає даних і підказки → null; немає даних, є підказка → картка з підказки; івент скінчився → null; 0 міток → null; лише гарбузи / лише привиди / обидва; дата кінця не вказана → показувати.
- **Rationale**: принцип VI; сам компонент лише читає/пише сховище й рендерить.
