# Quickstart: перевірка статистики активності й сповіщень

## Передумови

- Гілка `091-activity-stats`; `npm.cmd ci` у корені.
- Тести бази: `bash supabase/tests/run.sh` (WSL/Linux з Postgres; CI робить те саме).
- Живий сайт з базою: `npx.cmd vite --mode production` (звичайний `npm run dev` іде без Supabase).
- Прод: перед накатом `0075_activity_stats.sql` перевірити, що на базі є сліди 0061 (`map_point_authors`) і 0065 (`wiki_guides`). Міграції власник накочує вручну через SQL Editor, SQL передавати через буфер.

| Команда | Що доводить |

## 2. Ручний сценарій (сайт з базою)

1. Увійти адміном → «Адмін-панель → Статистика активності». Обрано поточний місяць, три картки.
2. Порівняти топ «Ціни скупників» з ручним підрахунком у SQL Editor (запит з `quickstart` нижче) — числа збігаються.
3. Відкрити гравця → виключити внесок з причиною → лічильник у картці −1 без перезавантаження. «Повернути» → +1.
4. «Скопіювати для Discord» → вставити в тестовий канал. Ніки з `_`/`*` показуються буквально, ніхто не пінгується, правок не треба (SC-002).
5. «Експорт CSV» → відкрити в Excel: колонки розкладені, кирилиця читається, числа як на екрані.
6. «Сповістити» біля 1 місця → шаблон з ніком, категорією, місцем, періодом → «Надіслати».
7. В іншому браузері увійти отримувачем → дзвіночок «1» одразу (SC-005) → відкрити → лічильник 0.
8. В адмінці «Історія сповіщень» протягом хвилини показує «прочитано» з часом (SC-006). Discord-статус протягом 15 хв: «доставлено» або «не доставлено — закриті особисті повідомлення або немає спільного сервера з ботом» (SC-007; поки бот на службовому сервері, другий варіант очікуваний).
9. Увійти модератором і відкрити `/admin?tab=stats` → відмова; у консолі `supabase.rpc('activity_top', …)` → помилка `42501`.

Контрольний запит для п. 2 (ціни, без виключень, ліміт 1):

```sql
select r.reporter, count(distinct (r.buyer_id, r.item_id, (r.created_at at time zone 'Europe/Kyiv')::date))
from price_reports r join profiles p on p.id = r.reporter
where r.kind = 'buyer' and p.role not in ('admin','moderator')
  and r.created_at >= '2026-11-01 00:00 Europe/Kyiv' and r.created_at < '2026-12-01 00:00 Europe/Kyiv'
group by 1 order by 2 desc limit 10;
```
