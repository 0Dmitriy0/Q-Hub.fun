# Contract: підсумок сеансу, який пише програма

## Запис

Програма пише в `public.game_sessions` лише upsert-ом з `onConflict: 'id'`:

```json
{
  "character_id": "<uuid персонажа сеансу>",
  "id": "<uuid рядка, згенерований програмою на старті сеансу>",
  "started_at": "2026-11-03T18:02:11.000Z",
  "ended_at":   "2026-11-03T19:40:00.000Z",
  "money_from": "2026-11-03T18:05:40.000Z",
  "money_to":   "2026-11-03T19:39:10.000Z",
  "money_start": 1250000,
  "money_end":   1310000,
  "money_gain":  420000,
  "money_flag":  false
}
```

- Поки гра йде — раз на хвилину (`BEAT`), `ended_at = зараз + LEASE`, як зараз.
- Гру закрито — фінальний upsert з `ended_at = зараз` (або остання відмітка, якщо програму перезапускали).
- Ще немає жодного стабільного зчитування балансу — шість полів `money_*` не передаються (лишаються `null`).
- Персонаж у програмі змінився посеред сеансу — поля `money_*` більше не оновлюються для цього рядка (research R5).
- Сеанс < 1 хв — `delete` за `id`, як зараз.

## Правила накопичення (`sessionmoney.cjs`)

| Подія | start | last | gain | flag |
|---|---|---|---|---|
| перше зчитування T у сеансі | T | T | 0 | false |
| T, `0 < T − last ≤ max_jump` | — | T | + (T − last) | — |
| T, `T < last`, `last − T ≤ max_jump` | — | T | — | — |
| T, `|T − last| > max_jump` | — | T | — | true |
| новий ключ (сеанс або персонаж) | відлік заново | | | |

`perHour()` для смужки Alt+Q лишається як є («Чистими» поточного сеансу).

## Що програма НЕ пише

Окремі зчитування, знімки, «продав / купив», будь-які інші таблиці обліку (`transactions`, `deals`) — FR-005, specs/040.

## Читання порогів

`select max_jump, min_minutes from money_rules` — на старті й раз на годину; без зв'язку — останні збережені, за відсутності — 5 000 000 і 5.
