# Research: Усі правила й закони QuantRP у програмі

Перевірено на форумі й у коді 2026-10-29.

## R1. Що на форумі

- «Правила серверу» — `index.php?/forum/10-правила-серверу/` з підрозділами 11, 12, 13, 66 (як зараз у `fetch-rules.mjs`).
- «Законодавча база Штату» — `index.php?/forum/36-законодавча-база-штату/`, 25 тем без підрозділів: кодекси (трудовий,
  дорожній, судовий, адміністративний, кримінальний, процесуальний, етичний), конституція, 17 законів.
- Обидва відкриваються без входу. Накази організацій — у `forum/21-державні-організації` і підрозділах фракцій (за
  замовчуванням не беремо, FR-002).

## R2. Як записані закони

- Кодекси: «Розділ I. …» / «РОЗДІЛ 2. …», «Стаття 1. Назва», пункти «1.1 …», «6.5 [Р] Викрадення…», підпункти
  «1.10.1 …». Покарання — наступним рядком: «Покарання: штраф $20 000.» — нинішній `chunks()` уже приклеює його до пункту.
- Нинішній `HEAD` (`^\d+\.\s+…`) не впізнає «Стаття N.» і «Розділ …» — вони стають звичайними абзацами, а пункт губить
  назву статті. **Decision**: заголовком вважати також `^(Стаття|РОЗДІЛ|Розділ|Глава)\s+[\dIVXLC]+\.?\s*…` (до 120 символів).
- Дорожній кодекс: перелік термінів «1) "Шосе" - …» — без номера пункту; лишаються абзацами (шматками до 700 символів).

## R3. Де жити оновленню

- **Decision**: функція Supabase `rules-sync` (Deno, як `assistant`) пише знімок у публічний бакет `rules`.
- **Rationale**: сайт деплоїться через FTP ~40 хв і лише з `main` — щодобове оновлення через деплой сайту неприйнятне;
  функція має доступ до мережі без CORS, service-ключ лише в секретах Supabase; сховище вже використовується.
- **Alternatives**: GitHub Actions пише `rules.json` у репозиторій і деплоїть сайт — повільно й засмічує історію;
  програма сама обходить форум — кожен гравець ходив би на форум (навантаження), і помилки розбору не бачив би адмін.

## R4. Розклад

- **Decision**: GitHub Actions `schedule` (щодня 01:00 UTC) → `POST /functions/v1/rules-sync` з заголовком
  `x-sync-secret: $RULES_SYNC_SECRET` (секрет у GitHub і в секретах функції). Кнопка адміна — той самий виклик із
  сесією `admin` (функція перевіряє роль у `profiles`).
- **Alternatives**: `pg_cron` + `pg_net` у базі — потребує розширень і SQL-налаштування поза міграціями проєкту.

## R5. Недоступне джерело й різниця

- **Decision**: функція бере попередній знімок зі сховища; для джерела з помилкою чи 0 пунктів — його теми з попереднього
  знімка без змін, у `rule_sources.error` — причина. Різниця по джерелу: `added / changed / removed` пунктів за ключем
  `url + n` (без номера — `url + перші 60 символів тексту`).

## R6. Програма

- **Decision**: `desktop/src/rules.cjs` як `mapref.cjs`: `GET <supabase>/storage/v1/object/public/rules/rules.json` з
  `If-None-Match`, кеш `%APPDATA%\Q-Hub\rules.json`; без мережі — кеш; без кешу — вбудована `src/data/rules.json`.
  Оновлення при старті й кожні 6 год (FR-013: «за добу» — з запасом). Плашка отримує `{ fetched, topics }` через міст
  (`rules-data`) і подію `rules-changed`.

## R7. Пошук і помічник

- Аліаси (FR-008): «кк» → кримінальн, «ак» → адміністративн, «пдр» / «дк» → дорожн, «пк» → процесуальн, «тк» → трудов
  (і `tk` — TeamKill, як зараз), «конституція». Слово-аліас шукає і в назві документа (`head`).
- Тип у результаті й уривку: «[Закон штату · Кримінальний кодекс, ст. 6.5] …», «[Правила сервера · Правила Зелених Зон,
  п. 1.2] …». Номер у кодексах — «ст.», у правилах — «п.».
- Підказка помічнику (`plan.ts`): відповідати лише з наданих пунктів; окремо — порушення правил сервера (адміністрація) і
  законів штату (у грі); кожне твердження — з документом і номером; немає пунктів — прямо сказати, номерів не вигадувати.
