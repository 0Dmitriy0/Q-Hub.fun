# Feature Specification: Зони на мапі (поля скарбів)

**Feature Branch**: `002-map-areas`

**Created**: 2026-10-24

**Status**: Implemented

**Input**: «Потрібно у карту добавити поле скарбів». Є 5 похилих скрінів з гри від гравця з червоною межею поля: аеропорт Лос-Сантоса (південь і схід), Палето-Бей (північне узбережжя й уздовж М2), за Форт-Занкудо дорогою на Палето-Бей (біля арочного мосту), в'їзд у Лос-Сантос з боку військової бази.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Гравець бачить поля скарбів на мапі (Priority: P1)

Гравець відкриває мапу сайту, вмикає в «Фільтрах» категорію «Поля скарбів» і бачить напівпрозорі ділянки вздовж пляжів. Клік по ділянці показує назву й примітку.

**Independent Test**: Створити зону під admin, відкрити мапу в анонімному вікні, увімкнути категорію — ділянку видно, клік показує назву.

**Acceptance Scenarios**:

1. **Given** у категорії є зони, **When** гравець вмикає категорію, **Then** зони видно заливкою кольору категорії з контуром; вимикає — зникають.
2. **Given** зона, **When** гравець клікає по ній, **Then** бачить назву, категорію й примітку.
3. **Given** у категорії лише зони (без точок), **When** гравець відкриває фільтри, **Then** категорію видно з лічильником зон.

### User Story 2 — Admin малює й прибирає зону (Priority: P1)

Admin у вкладці «Адмін» натискає «Нова зона», обирає категорію й назву, клікає по мапі точки контуру (бачить лінію, що будується), за потреби прибирає останню точку і натискає «Зберегти зону». Неправильну зону видаляє з її спливаючого вікна.

**Independent Test**: Намалювати трикутник, зберегти, оновити сторінку — зона на місці; видалити — зникла.

**Acceptance Scenarios**:

1. **Given** режим «Нова зона», **When** admin клікає по мапі, **Then** точки додаються до контуру й видно лінію; «Прибрати останню» видаляє останню.
2. **Given** менше 3 точок, **When** «Зберегти зону», **Then** збереження заблоковане з підказкою.
3. **Given** збережена зона, **When** admin натискає «Видалити» в її вікні й підтверджує, **Then** зона зникає з мапи й бази.
4. **Given** користувач не admin, **When** намагається додати зону (навіть напряму через базу), **Then** база відмовляє.

### User Story 3 — Перші поля скарбів (Priority: P2)

На мапі вже є контури 5 полів зі скрінів — admin лише перевіряє й за потреби видаляє та перемальовує.

### Edge Cases

- Контур перетинає сам себе — дозволено (малює як є); admin перемальовує.
- Зона частково в морі — дозволено.
- Видалили категорію — її зони видаляються разом з нею (як точки).
- Дуже багато точок (> 500) — база відмовляє.

## Requirements *(mandatory)*

- **FR-001**: Зона — багатокутник з 3–500 вершин у метрах гри (x −6000…6800, y −4400…8500), категорія, назва (≤ 160), примітка (≤ 600).
- **FR-002**: Бачать усі (зокрема гості); додає, змінює й видаляє лише admin — правилами бази (конституція, принцип II).
- **FR-003**: Зони показуються в шарі своєї категорії й вмикаються тим самим фільтром, що й точки.
- **FR-004**: Категорія «Поля скарбів» — у групі «Шари мапи» (поруч із «Назвами місць» і «Зеленими зонами»), з'являється міграцією; за замовчуванням вимкнена у фільтрах.
- **FR-005**: Інструмент admin: нова зона кліками, прибрати останню точку, скасувати, зберегти; видалити зону з її вікна.
- **FR-006**: Кожна зміна правил доступу має SQL-тест (дозвіл і заборона для anon, user, admin) — принцип VI.

## Success Criteria *(mandatory)*

- **SC-001**: Admin малює й зберігає поле з 15–20 точок менш ніж за 2 хвилини.
- **SC-002**: Гравець бачить поля після одного кліку по категорії у фільтрах.
- **SC-003**: Жоден не-admin не може створити, змінити чи видалити зону (SQL-тест).

## Assumptions

- Поле скарбів — смуга піску між червоною лінією на скріні й водою (власник не уточнив; межі admin підправляє сам).
- Скріни надіслав гравець — дозволене джерело (принцип IV). Якщо з'ясується, що це дані іншого фан-сайту, контури з US3 видаляються.
- Редагування окремих вершин наявної зони — поза межами: видалити й перемалювати.
- Зони в «Карті для гри» (текстури мінімапи) — поза межами цієї версії.
