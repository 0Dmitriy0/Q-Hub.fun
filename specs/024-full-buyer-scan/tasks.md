## Phase 4: User Story 2 — товар, що промайнув один раз, не губиться (Priority: P1)

**Goal**: товари з межами — з одного кадру (як зараз); без меж — двома однаковими зчитками **в межах одного
відкриття**; «бачено, не підтверджено» показується як `pending`; адмін бачить товари без меж.

**Independent Test**: `junk-fast.json` — усі товари з межами, видимі хоч раз, прочитано; товари без меж, видимі один
раз, не надіслані й у `pending`; 0 хибних цін (quickstart.md, крок 5).

## Implementation Strategy

1. **MVP = Phase 1 + 2 + US1** — гравець бачить «N з M» і прокручує; це саме по собі закриває головну втрату (товари,
   до яких ніхто не прокручує). Випустити, перевірити, що «Риба» оновлюється (SC-003).
2. **+ US2** — товари без меж; паралельно адмін заповнює межі 6 товарів «Мотлоху» (SC-004) — без нової версії.
3. **+ US3** — обрізані рядки.
4. **+ FR-010** — невідомі назви.

Кожен крок — окремий випуск; журнал оновлень доповнюється тим самим днем, якщо випуск того ж дня.
