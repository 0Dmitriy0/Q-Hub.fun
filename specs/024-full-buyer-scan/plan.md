# Implementation Plan: Усі ціни скупника — навіть ті, що не вміщаються у вікно

**Branch**: `024-full-buyer-scan` (робота — у власній гілці, у `main` — після зелених тестів) | **Date**: 2026-10-29 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/024-full-buyer-scan/spec.md`

## Summary

Програма вже читає вікно скупника щокадру (~2 с) і приймає ціну з одного кадру, якщо в товару є межі
(`desktop/src/pricescan.cjs`). Товари, до яких гравець не прокрутив, вона не бачить, а прокручувати сама не має права
(принцип I). Тому:

1. **Покриття вікна** — нова чиста логіка `coverage` у `pricescan.cjs`: «прочитано N з M» за поточне відкриття вікна.
2. **Підказка гравцю** — смужка `strip.html` отримує режим «скупник»: показується, поки відкрите вікно скупника
   (навіть коли плашка Alt+Q закрита), і пише «Шкури: прочитано 9 з 32 — прокрути список, щоб дочитати» → «32 з 32 ✓».
3. **Точність** — підтвердження двома кадрами рахується в межах одного відкриття вікна (зараз — назавжди), обрізані
   рядки на краю (низька висота рядка розпізнавання) відкидаються до розбору.
4. **Адмін** — фільтр «без меж» на сторінці «Ціни» (межі там уже редагуються) і таблиця
   `buyer_unknown_items` для назв, яких немає в Q-Hub (лише пропозиції, без автододавання).

## Technical Context

**Language/Version**: JavaScript CommonJS (Electron 37) — програма; TypeScript/React — сайт і плашка; SQL (Postgres / Supabase)

**Primary Dependencies**: наявні — tesseract.js 6, Electron, Supabase JS; нових немає

**Storage**: Supabase Postgres: `buyer_items` (межі `min_price`/`max_price` — без змін), нова `buyer_unknown_items`

**Testing**: `node --test` (desktop/src/*.test.cjs) — логіка покриття, підтвердження й обрізаних рядків; `vitest` —
`shotParse` (сайт і програма спільно); SQL-тест у `supabase/tests/` для `buyer_unknown_items`

**Target Platform**: Q-Hub Desktop (Windows 10/11), сайт q-hub.fun (сторінка «Ціни» для адміна)

**Project Type**: desktop app + web з спільною базою

**Performance Goals**: розбір кадру не повільніший за нинішній (~2 с на кадр); оновлення смужки — не частіше ніж раз на кадр

**Constraints**: принцип I — програма нічого не натискає й не прокручує; принцип IV — жодної ціни з невпевненого
розпізнавання; принцип V — черга без інтернету як зараз; смужка не забирає фокус і пропускає кліки в гру

**Scale/Scope**: 10 скупників, ~120 товарів; найдовші списки — «Мотлох» 35, «Шкури» 32, «Риба» 14

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Принцип | Перевірка | Стан |
|---|---|---|
| I. Зовнішній інструмент | Програма лише підказує «прокрути»; не натискає, не прокручує, не читає пам'ять гри | ✅ |
| II. Права — у базі | `buyer_unknown_items`: вставляє `authenticated` лише свої рядки, читає й видаляє лише `admin` (RLS); автододавання товарів немає | ✅ |
| III. Знімки приватні | Зберігається лише розпізнаний текст назви (без знімка); знімки не відправляються | ✅ |
| IV. Перевірені дані | Без меж — лише два збіжні кадри в межах одного відкриття; обрізані рядки відкидаються; поріг `MIN_SCORE` не знижується | ✅ |
| V. Лише додає, офлайн | Ціни — у наявну чергу; невідомі назви — лише вставка; без зв'язку пропускаються (не критично) | ✅ |
| VI. Тести | `node --test` для `coverage`, `pricePicker`, обрізаних рядків; SQL-тест дозволу й заборони для `buyer_unknown_items` | ✅ |

## Phases (для /speckit-tasks)

1. **P1 — покриття й підказка (US1)**: `coverage()` + тести → `vision.cjs` викликає й віддає `onCoverage` →
   режим смужки «скупник» у `main.cjs` і `strip.html`.
2. **P1 — точність (US2)**: підтвердження двома кадрами в межах відкриття; лічильник не рахує «бачено, не
   підтверджено»; адмін-фільтр «без меж» на «Цінах».
3. **P2 — обрізані рядки (US3)**: висота рядка в `lines()`, відкидання в `shotParse`, тести на кадрах із фікстур.
4. **P3 — невідомі назви (FR-010)**: міграція 0029 + SQL-тест + вставка з програми + список для адміна.
5. **Журнал оновлень** і перевірка за `quickstart.md` на живій грі.
