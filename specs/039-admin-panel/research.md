# Research: Адмін-панель для розробників (039)

Стан бази й коду звірено 2026-11-02.

## R1. Доступ до `/admin`

- **Decision**: маршрут `/admin` у `App.tsx` рендерить `<NotFound/>`, якщо `role !== 'admin'`, так само для гостя. Посилання «Адмінка» в `Layout.tsx` показується лише адміну. Захищає не це, а функції бази (R2–R6).
- **Rationale**: FR-001 і FR-004. Конституція II: інтерфейс лише ховає.
- **Alternatives**: сторінка «Немає доступу» — відкинуто, бо видає існування панелі.

## R2. Черги: атомарний розбір

- **Decision**: кожна дія — одна функція `security definer`, яка починає з `delete … returning` рядка черги. Якщо рядка вже немає, вона кидає `P0002 'Цей рядок уже розібрано'`. Так два адміни не додадуть товар двічі (FR-010).
- **Невідомий товар** (`admin_unknown_resolve`):
  - `add` — новий товар у `items` (назва, категорія) або наявний `item_id`, плюс рядок `buyer_items` з межами 0;
  - `alias` — текст дописується в `items.aliases` наявного товару (без дублів, без регістру);
  - `drop` — лише видалення рядка.
- **Межі** (`admin_limit_resolve`): `fix` оновлює `buyer_items.min_price/max_price` (перевірка `0 < min < max`), `drop` лише видаляє рядок.
- **Непідтверджені ціни**:
  - читання — `admin_price_pending()`: як `price_pending`, плюс ніки тих, хто вніс. Сам `price_pending` свідомо без авторів, тому лишається як є;
  - «Підтвердити» — звичайне внесення ціни адміном із сайту (`source <> 'desktop'`): тригер 0043 ставить його одразу поточним. Нового механізму немає;
  - «Відкинути» — `admin_price_reject(buyer, item, price)` видаляє голоси за цю ціну, новіші за `price_at`.
- **Чернетки міток**: лише `count(*) where status = 'new'`. Адмін і так читає всі чернетки (0019), тож функція не потрібна.
- **Alternatives**: прямі `delete`/`update` з клієнта у два кроки — відкинуто, бо між кроками інший адмін може розібрати той самий рядок.

## R3. Псевдоніми товарів у програмі

- **Знахідка**: `items.aliases text[]` є з 0001, але програма його не читає. `bestItem` (`desktop/src/lib/shotparse.cjs`) зіставляє лише з `items.name`. `buyer_aliases` — це псевдоніми **id скупника** (0040), а не назв товарів.
- **Decision**:
  - програма вантажить `items(name, aliases)`, і чиста функція `expandAliases(items)` додає для кожного псевдоніма копію товару з `name = alias`;
  - `bestItem` не змінюється;
  - дія «Це вже є» пише в `items.aliases`.
- **Rationale**: мінімальна зміна, `shotparse` спільний і покритий тестами.
- **Alternatives**: окрема таблиця псевдонімів на рівні скупника — відкинуто, бо назва товару однакова в усіх скупників.

## R4. Ролі

- **Знахідка**: клієнтам видано лише `update (name, avatar_url)` на `profiles` (0001), тож роль змінити напряму неможливо. Ім'я Discord — `profiles.name`, нік — `profiles.nick`.
- **Decision**: `admin_set_role(p_user, p_role)`:
  - перевіряє `is_admin()`;
  - забороняє міняти власну роль з `admin`;
  - бере `for update` на всіх рядках `role = 'admin'` і забороняє зняти роль з останнього.

  Пошук — `admin_find_accounts(q)`: `ilike` по `nick` і `name`, від 2 символів, до 20 рядків. Персонажі віддаються як `json` лише з `name` і `static_id`.
- **Alternatives**: дати адміну `update (role)` через RLS-політику — відкинуто, бо політика не вміє заборонити «останнього адміна».

## R5. Стан програми й версії

- **Знахідка**: `app_presence(user_id, seen_at)` без версії; `app_ping()` без аргументів.
- **Decision**:
  - `alter table app_presence add version text, add first_seen timestamptz default now()`;
  - `drop function app_ping()`, а натомість `create function app_ping(p_version text default null)`. Старі програми кличуть `rpc('app_ping')` без аргументів, і PostgREST знаходить функцію з типовим значенням, тож вони не ламаються. `version` перевіряється за `^\d+\.\d+\.\d+$`, інакше записується `null`;
  - `admin_app_stats()` повертає `json`:
    - `online_3m`, `online_24h`;
    - `versions[]` за 7 днів, з `null` → «стара версія»;
    - `ai`: запити й гравці сьогодні та скільки досягли ліміту 150 із `assistant_take`;
    - `downloads`: `n` і `since`.
- **Остання версія в релізі**: GitHub API `GET /repos/0Dmitriy0/Q-Hub.fun/releases/tags/desktop-latest` з браузера (CORS дозволено, 60 запитів на годину без ключа). Версія — з назви файла `Q-Hub-Setup-(\d+\.\d+\.\d+)\.exe` серед `assets`; старі файли workflow видаляє, тож він там один. Не вдалося — позначки «остання» немає, решта працює.
- **Alternatives**: версія в окремій таблиці подій — надлишково для «на чому зараз сидять».

## R6. Навчальні знімки

- **Знахідка**: програма кладе `training/<uid>/<час>.jpg` і поруч `.json` з `{label, note, size, version, at}` (`main.cjs`, 0018). Читає й видаляє лише admin.
- **Decision**:
  - список — `admin_training_shots(p_before timestamptz, p_limit int = 50)`: `storage.objects` з `bucket_id = 'training'` і `name like '%.jpg'`, новіші першими, плюс нік автора з `profiles` за першою частиною шляху;
  - мініатюри — `createSignedUrls(names, 600)`;
  - мітки — завантаженням `.json` порції паралельно, до 50 маленьких файлів;
  - фільтр за міткою — по завантажених порціях;
  - видалення — `storage.remove([jpg, json])`, політика 0018.
- **Alternatives**: дублювати мітку в окрему таблицю — додало б запис від програми й міграцію даних, а для обсягу «сотні» це не потрібно.
