# Data Model: нормалізація запиту

Даних у базі немає — лише константи й типи в коді.

## Константи (`src/desktop/rulesSearch.ts`)

| Назва | Тип | Зміст |
|---|---|---|
| `LAYOUT_UA` | `Readonly<Record<string, string>>` | клавіша англійської (США) → літера української: 26 літерних клавіш + `; ' [ ] , .` (32 літери) + `` ` `` → `'` (research R3) |
| `LAYOUT_RU` | `Readonly<Record<string, string>>` | як `LAYOUT_UA`, але `s→ы`, `]→ъ`, `'→э`, `` ` ``→`ё` |
| `RU_TO_UA` | `Readonly<Record<string, string>>` | приведення для пошуку: `ы→и`, `э→е`, `ё→е`, `ъ→''` |
| `QUERY_SEP` | `RegExp` | роздільник між цифрами: `/ \ , - _ ю б .`, пробіли навколо або самі пробіли |

Обернені таблиці (кирилиця → латиниця) будуються з `LAYOUT_UA` і `LAYOUT_RU` один раз при завантаженні модуля; конфлікти (однакова латиниця) неможливі, бо таблиці — бієкції на своїх клавішах.

## Типи

- `FixedSearch<T> = { result: T; shown: string | null }` — `shown` — виправлений запит, якщо результат знайдено за ним; `null` — показано за набраним.
- `Ask.fixed?: string` — у плашці (`Bar.tsx`) і демо (`BarDemo.tsx`): текст для підказки «Показано результати для: …».

## Правила

- `normalizeQuery` ідемпотентна: `normalizeQuery(normalizeQuery(q)) === normalizeQuery(q)`.
- Варіанти з `layoutVariants` — не більше 2, без дублів і без варіанта, що збігається з `normalizeQuery(query)`.
- Порядок варіантів: український, потім російський (за рівності — український, FR-004).
