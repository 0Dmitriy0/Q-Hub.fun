# Quickstart: перевірка нормалізації запиту

## Автоматично

`npx.cmd vitest run src/desktop/rulesSearch.test.ts src/desktop/barSearch.test.ts` — обов'язкові тести на всі приклади специфікації:

| Що | Очікування |
|---|---|
| `normalizeQuery`: «3/3», «3,3», «3ю3», «3б3», «3 3», «3-3», «3 / 3» | «3.3» |
| `normalizeQuery`: «3/3/1», «3-3/1», «3ю3ю1» | «3.3.1» |
| `normalizeQuery`: «кк/пдр», «3/», «/3», «зелена-зона», «ЗЕЛЕНА» | без змін (лише регістр) |
| `toLayout`: «lr», «ghfdbkf», «ufhf;», «GHFDBKF» → ua | «дк», «правила», «гараж», «правила» |
| `toLayout`: «вь» → en; «'ktrnhjyysq» → ru | «dm»; «електронний» |
| `layoutVariants`: «dm pfkty» з відомим «dm» | «dm зелен…» — dm не переведено |
| `searchRules` на вбудованій копії правил | кожен варіант роздільника = результат «3.3» (і «КК 6/7» = «КК 6.7») |
| `fixedSearch`: «ghfdbkf», «3/3 lr» | результати як «правила», «3.3 дк»; `shown` = «правила», «3.3 дк» |
| `fixedSearch`: «dm», «кк 6.5», «зелена зона» | `shown = null`, результати як без зміни |
| Наявні тести `rulesSearch.test.ts` | усі зелені, без змін (SC-003) |

`npm.cmd test`, `npm.cmd run typecheck` — зелені.

## Вручну (програма)

1. Закрити запущену Q-Hub власника, `cd desktop && npm.cmd start` (пам'ять: перезапуск після зміни програми).
2. Alt+Q → режим «Пошук»:
   - «3/3 lr» → статті 3.3 Дорожнього кодексу, над ними «Показано результати для: 3.3 дк»;
   - «3.3 дк» → ті самі, без підказки;
   - «ufhf;» → гаражі на мапі з підказкою «гараж»;
   - Shift+Enter з «ghfdbkf ptktyj] pjy» → ШІ відповідає про зелені зони.
3. Сайт, сторінка програми (демо плашки): «ghfdbkf» → підказка й пункти правил.
