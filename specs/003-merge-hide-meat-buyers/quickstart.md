# Quickstart: перевірка злиття «М'ясо» → «Шкури»

## Перед міграцією (для порівняння, SC-002)
У Supabase → SQL Editor запам'ятати числа:
- товарів у `meat` і `hide` у `buyer_items` (зараз 8 і 32);
- точок історії `meat` і `hide` у `price_history` (зараз `meat` — 57);
- повідомлень `meat` і `hide` у `price_reports`.

## Автоматичні тести
```
bash supabase/tests/run.sh          # у CI; там і buyers_merge_test.sql (R8)
npm.cmd test                        # сайт
cd desktop && npm.cmd test          # програма: pricescan «м'ясо» → hide
```
Очікується: усе зелене.

## Після застосування міграції
1. **SQL Editor**: `select id from buyers order by sort` — 9 рядків, `meat` немає.
   Товарів у `hide` = 32 + 8 = 40; точок історії `hide` = було `hide` + 57; повідомлень — сума. Дублів немає.
2. **Сайт, анонімно** → «Ціни»: вкладки «М'ясо» немає, у «Шкурах» є «М'ясо кабана» з тією ж ціною й позначкою,
   історія на графіку така ж, як до злиття (US1).
3. **Сайт, гравець з ніком і статіком**: внести ціну «М'ясо оленя» у «Шкурах» — приймається (US2.1).
4. **Стара програма** (до оновлення) у вікні скупника з м'ясом — ціни приходять у «Шкури», у `update.log`/`vision.log`
   немає помилок про скупника (US2.2).
5. **Нова програма**: те саме, у журналі `vision.log` — `prices hide: …`, а не `prices meat` (FR-007).
6. **Таймер**: у «Шкур» один час наступної зміни, пізніший з двох (US3).
7. Повторно запустити міграцію в SQL Editor — без помилок, числа з п. 1 не змінились (FR-008).
