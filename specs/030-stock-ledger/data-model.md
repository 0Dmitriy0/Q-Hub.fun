# Data Model: Правдивий склад і зручніший облік

Схема бази не змінюється. Нові сутності існують лише в пам'яті програми й у чистих функціях.

## Продаж (від зору до main)

| Поле | Тип | Звідки |
|---|---|---|
| txId | uuid | `transactions.id` запису «Продаж фарму» (`autoRecords` → `.select('id')`) |
| amount | int | сума запису |
| buyerId | text \| null | скупник з `place`, якщо вікно читалось ≤ 10 хв тому |
| prices | `{ item_id: price }` \| null | ціни, розпізнані в цьому відкритті вікна |
| at | ms | час запису |

## Пропозиція списання (main, у пам'яті)

- **Ключ**: `txId`. Один запис обліку — одна пропозиція (FR: кілька продажів поспіль не зливаються).
- **Стан**: `pending` → `confirmed` | `declined` | `expired` (10 хв). Після `confirmed` кнопка «Скасувати» доступна 10 с і переводить у `undone`.
- Зберігається лише в пам'яті. Після перезапуску програми пропозиції зникають, і запис обліку лишається як є (принцип IV: краще нічого, ніж вигадане).

## Кандидат (`saleGuess`)

```text
{ kind: 'one',  lines: [{ item, qty, price, farm }] }   — один товар
{ kind: 'all',  lines: [...] }                           — «Продати все»
{ kind: 'manual', items: [{ item, price, have }] }       — вибір вручну
```

`farm`: скільки з `qty` записати парою «Нафармив», бо на складі бракує (FR-002a). `qty − farm` ≤ склад.

## Угоди списання (`deals`, наявна таблиця)

На кожен рядок кандидата:
- `op = 'farm'`, `qty = farm`, `price = 0`, `tx_id = txId` — якщо `farm > 0`; час на 1 мс раніше за продаж, щоб `ledger()` спершу додав товар;
- `op = 'sell'`, `qty`, `price`, `tx_id = txId`, `category = ''`.

Правило видалення (R5): видалення угоди видаляє запис обліку лише тоді, коли `transactions.source = 'deal'`.

## Порада по товару складу (`advise`, наявна)

Додається:
- `wait: boolean` — `pos !== null && pos < WAIT` (WAIT = 40);
- окремий список `unsold` — товари складу, яких немає в жодного скупника: `{ item, qty, cost }`.

## Фільтр історії (`txFilter`)

`{ cat?: string; account?: 'cash' | 'card'; period: Period; source?: 'auto' | 'manual' }`
- `auto` = `source ∈ {desktop, reconcile}`;
- `manual` = решта;
- перекази (`transfer`) показуються в обох, бо гравець їх робить сам або програма.

## Чистий за годину (`perHourByCat`)

Вхід: записи обліку й ігрові сесії. Вихід:

```text
[{ cat, net, ms, perHour | null }]
```

`perHour = null`, коли `ms < 15 хв`.
