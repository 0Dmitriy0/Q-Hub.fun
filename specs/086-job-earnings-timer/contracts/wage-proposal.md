# Contract: пропозиція заробітку з таймера

Програма вставляє рядок у наявну `public.wiki_proposals` від імені гравця (сесія Supabase головного процесу). Нових таблиць, полів, політик і функцій немає.

```js
sb.from('wiki_proposals').insert({
  section: 'job',
  target_id: label.id,               // jobs.id; інакше QH014 «Такої сторінки немає»
  kind: 'edit',
  data: { pay: mergePay(job.pay, label.level, '≈30 000 $/год (вимір 30 хв, 14.11.2026)') },   // ≤ 300 знаків, див. нижче
  source: 'game',
  source_note: 'Таймер Q-Hub: 30 хв чистого часу, +15 000 $, 30 000 $/год; сумнівних стрибків немає; баланс не видно 0 хв. id:k3f9…',  // ≤ 300
}).select('id').single()
```

- `author`, `status='pending'`, `base_version` ставлять за замовчуванням і тригер `wiki_proposal_new`.
- RLS «wiki proposals: add own»: лише `author = auth.uid()` і `pending` — без входу insert відхиляється (FR-018, SC-008).
- Помилки, які показуються гравцю як є: QH001 (бан), QH002 (ліміт на розгляді), QH014 (немає роботи).
- Модератор бачить пропозицію в черзі адмінки як звичайну правку роботи: diff `Заробіток: <старе> → <нове>` і примітку джерела з даними виміру; рішення — `wiki_decide`, відкат — `wiki_revert`.
- Статус для історії: `select id, status from wiki_proposals where id = any(:ids)` (RLS «read» — автор бачить свої).

## Зведення заробітку по рівнях (`mergePay`)

Поле `jobs.pay` — один текст на роботу (≤ 300). Щоб пропозиція для одного рівня не стерла інші, програма будує новий текст з **поточного** `pay` (читає `jobs.pay` перед надсиланням):

- частини тексту розділені « · » чи переносом рядка; частина рівня — `Рівень N: …`;
- є частина `Рівень N:` того самого рівня → замінюється новою;
- немає → нова частина дописується, частини рівнів сортуються за N зростанням; решта тексту (без «Рівень …») лишається на початку як є;
- результат > 300 знаків → надсилається лише нова частина `Рівень N: …`, а в `source_note` — «текст довідника задовгий, звести вручну»; модератор редагує перед публікацією (`accepted_edited`).

Приклад: `pay = 'Залежить від врожаю · Рівень 1: ≈18 000 $/год (…)'`, вимір рівня 3 → `'Залежить від врожаю · Рівень 1: ≈18 000 $/год (…) · Рівень 3: ≈30 000 $/год (вимір 30 хв, 14.11.2026)'`.

`source_note` (≤ 300): `Таймер Q-Hub: рівень 3, 30 хв чистого часу, +15 000 $, 30 000 $/год; сумнівних стрибків немає; баланс не видно 0 хв. id:<measureId>`.
