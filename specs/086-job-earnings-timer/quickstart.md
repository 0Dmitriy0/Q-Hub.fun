# Quickstart: перевірка таймера заробітку

## 1. Модульні тести

```
cd desktop && npm.cmd test
```

Очікується: `jobtimer.test.cjs` зелений — старт чекає баланс; сума зростань; витрати не віднімаються; пауза не рахує час і гроші; стрибок > max_jump → flag; `perHour` null до 1 хв; blindMs; відновлення після перезапуску → pause+interrupted; історія ≤ 200, середнє по роботі; `canPropose` і причини; текст `pay` ≤ 300 і `source_note` ≤ 300; `Label`: рівень 1–100 чи null, назва власного 1–60; групи «робота + рівень» і власні без регістру; `mergePay`: заміна свого рівня, дописування нового з сортуванням, інші частини не зникають, > 300 → лише новий рівень.

## 2. Програма (без гри — підставний баланс)

Закрити Q-Hub власника → `npx.cmd vite build -c vite.app.config.ts` → `cd desktop && npm.cmd start`.

1. Alt+T → вікно «чекаю баланс» (без гри баланс не приходить) — Edge Case.
2. У грі на роботі: Alt+T → відлік; заробити → «Зароблено» й $/год оновлюються ≤ 5 с (US1, FR-008).
3. Пауза → купити щось → продовжити → заробіток не зменшився, час паузи не врахований (US2, SC-003).
4. Закрити Alt+Q → рухатися, стріляти — вікно не заважає (SC-004).
5. Alt+T → підсумок; обрати роботу → в історії видно вимір і середнє по роботі (US3).
6. Закрити програму посеред відліку → запустити → вимір на паузі з позначкою «перервано» (FR-011, SC-005).
7. Налаштування → змінити клавішу таймера → нова працює, стара ні (FR-001).

## 3. Пропозиція в довідник (US4)

1. Вимір ≥ 10 хв, робота з довідника, без стрибків → «Запропонувати в довідник» → «Надіслано на перевірку».
2. Сайт → Адмінка → черга довідника: правка роботи, diff «Заробіток», примітка з даними виміру.
3. Опублікувати → у довіднику новий заробіток; в історії таймера — «опубліковано».
4. Вимір 5 хв / «Без роботи» / зі стрибком — кнопка недоступна з причиною (FR-014).
5. Вийти з акаунта → «Запропонувати» → пояснення, вимір лишився (FR-018).

## 4. Підпис: робота з рівнем і власний замір (US3)

1. Стоп → «Ферма», рівень 3 → в історії «Ферма · рівень 3»; ще вимір рівня 1 → окрема група «Ферма · рівень 1», середні не змішуються.
2. Стоп → «Власний замір» → «риболовля на пірсі» → окрема група; «Риболовля на пірсі » з пробілом — та сама група.
3. Рівень 0, 101, 2.5, «abc» — поле не приймає з поясненням; порожня назва власного — не зберігається.
4. Новий вимір → підсумок уже має «Ферма · рівень 3» з останнього (FR-010a).
5. Власний замір / «Ферма» без рівня → «Запропонувати» недоступна з причиною (FR-014).
6. У довіднику «Ферми» заробіток `Рівень 1: …` → надіслати вимір рівня 3 → у черзі diff дописує `· Рівень 3: …`, рівень 1 не зник (mergePay).
