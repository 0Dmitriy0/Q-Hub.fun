# Research: Гарний і читабельний текст відповідей

## Що зараз не так (знахідки в коді)

- `.bans` (`src/desktop/bar.css:107`) без `white-space: pre-line` — переноси рядків у відповіді ШІ зникають, усе зливається в один абзац. У `.brule p` (`bar.css:96`) `pre-line` є, тому пункти правил переноси зберігають.
- Промпт (`supabase/functions/assistant/plan.ts:11–12`): «звичайним текстом: одне-два короткі речення», «до чотирьох речень» — модель і не дає структури.
- `cites()` (`barParts.tsx:70`) уже виділяє «(…, п. 1.3)» — розбирач має викликати його всередині абзаців і пунктів.
- Згортання довгого пункту — `-webkit-line-clamp` на `<p>` (`bar.css:97`); з кількома блоками всередині воно не працює.

## R1. Чим розбирати розмітку

- **Decision**: власний розбирач `richText.ts` лише для підмножини: абзаци (порожній рядок чи перенос), список (`- `, `• `, `* `, `1. `, `1) ` на початку рядка), `**жирне**`. Решта (`#`, `_`, таблиці, посилання) — звичайний текст; на початку рядка `#`/`##` просто зрізаються.
- **Rationale**: потрібна вузька, передбачувана граматика; результат — React-вузли без HTML (безпека); ~60 рядків, легко покрити тестами; бандл не росте.
- **Alternatives considered**: `marked`/`markdown-it` + санітайзер — HTML-рядок через `dangerouslySetInnerHTML`, потрібен DOMPurify, +30–40 КБ, підтримує те, що ми хочемо заборонити (заголовки, таблиці, картинки). `react-markdown` — +~50 КБ з remark, надлишково.

## R2. Як змусити ШІ відповідати структуровано

- **Decision**: у SYSTEM замінити «звичайним текстом: одне-два короткі речення» на правило формату: перше речення — головна думка (так/ні, сума, строк); якщо пунктів 2+ — список, кожен з нового рядка з «- »; `**жирне**` — лише для сум, строків і ключового слова, не більше трьох на відповідь; без заголовків, таблиць і вкладених списків; для простих питань (ціни) — одне-два речення, як і було. Посилання «(документ, п. N)» — у кінці пункту, як зараз.
- **Rationale**: перша фраза відповідає SC-001; список — SC-002; обмеження жирного не дає «новорічної ялинки».
- **Alternatives considered**: структурований JSON (`{main, points[]}`) — ламає наявний `clean()` і `checkRefs`, історію й «Окремо»; надлишково.

## R3. Згортання довгого пункту з блоками

- **Decision**: згортати контейнер `.rich.clamp` по висоті: `max-height: calc(1.55em * 4)`, `overflow: hidden` і м'яке згасання знизу `mask-image: linear-gradient(#000 60%, transparent)`.
- **Rationale**: `line-clamp` не працює для кількох блоків; маска показує, що далі є текст.
- **Alternatives considered**: обрізати текст рядком у JS — ріже посеред слова й розмітки.

## R4. Типографіка й контраст

- **Decision**: основний текст `--fg` (#f4f7fb) на `#18212d` — ~15 : 1; другорядний `--muted` (#8b9bb0) — ~5,8 : 1; `--faint` (#7a8ba1) — ~4,6 : 1 (≥ 3 : 1). Відповідь ШІ 15.5px / 1.6, пункти правил 14.5px → 15px / 1.6; абзаци — проміжок 0.55em; список — відступ 1.2em, маркер кольору акценту; `strong` — 700 і `--fg`; `max-width: 75ch` для тексту. Покарання `.bpen` — окремий рядок з іконкою-міткою зліва від тексту пункту; номер пункту `.bpunkt` лишається моно, текст — без змін ваги.
- **Rationale**: FR-007/FR-008; кольори вже є в темі, нових токенів не треба.
- **Alternatives considered**: збільшити шрифт до 16–17px — плашка вузька, більше прокрутки посеред гри.

## R5. Копіювання

- **Decision**: `plainText(text)` з того самого розбору: абзаци через `\n\n`, пункти — `• ` чи `N. `, жирне — без зірочок; позначки пунктів лишаються як є «(…, п. 1.3)».
- **Rationale**: FR-006 / SC-003: Discord і чат гри покажуть зірочки буквально.
