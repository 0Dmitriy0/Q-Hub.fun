# Data Model: Гарний і читабельний текст відповідей

Нових даних у базі й сховищі немає. Модель — лише в пам'яті, результат розбору тексту при показі.

## RichDoc (результат `parseRich`)

`RichDoc = Block[]`

| Тип блока | Поля | Звідки |
|---|---|---|
| `para` | `spans: Span[]` | один чи кілька рядків підряд без маркера списку |
| `list` | `ordered: boolean`, `start: number` (номер першого пункту: «3.» → 3, для маркованого — 1), `items: Span[][]` | рядки підряд з маркером `-`/`•`/`*` (ordered=false) чи `1.`/`1)` (ordered=true) |

`Span = { t: 'text', v: string } | { t: 'bold', v: string }`

Позначки пунктів «(…, п. N)» не окремий тип: їх виділяє наявний `cites()` під час показу кожного `text`/`bold`.

## Правила

- Порожні рядки поспіль = один розрив між блоками; порожніх блоків немає.
- Рядок без маркера одразу після пункту списку закриває список і починає абзац.
- `**…**` без пари — звичайний текст разом із зірочками.
- `#`, `##`, `###` на початку рядка — зрізаються (рядок стає абзацом).
- Тип списку визначає перший пункт; змішані маркери поспіль — той самий список.
- Маркер `*` — лише зірочка з пробілом; `**` на початку рядка — жирне, не список. «1.1 Текст» — номер пункту, не список.
- Рядок із самого маркера без тексту пропускається.
- Вхід порожній → `[]`; вхід без структури → один `para`.

## Наявні сутності (без змін)

- **Відповідь ШІ** — `Ask.reply: string` (сирий текст з легкою розміткою), історія зберігає її як є.
- **Пункт правил** — `RuleHit { kind, n, topic, url, h, s }`; `s` розбивається `splitPenalty` на `body / pen / more`, далі `body` — через `parseRich`.
