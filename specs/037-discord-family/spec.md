# Feature Specification: Discord сайту — сервер сім'ї CORE

**Feature Branch**: `037-discord-family`

**Created**: 2026-11-01

**Status**: Draft

**Input**: User description: "Discord канал сайту будем використовувати сімейний діскорд канал щоб не створювати новий"

## Контекст

- **Окремого Discord у Q-Hub немає.** Єдине посилання на Discord на сайті — поле «Discord Q-Hub для питань» в інструкції до мапи; його вписує адмін, і воно порожнє, доки не впишуть (перевірено 2026-11-01).
- **Рішення власника:** не створювати новий сервер, а використовувати Discord сім'ї CORE.
- **Де Discord потрібен:**
  - питання й зворотний зв'язок («не знайшов відповіді» — specs/032, 034);
  - повідомлення про помилки замість чи поруч з GitHub;
  - інструкція до мапи.
- **Пов'язані рішення:** це змінює 033 («зроблено сім'єю CORE»). Там я заклав «без посилань на ресурси сім'ї», бо ресурси сім'ї — ближче до реклами. Тепер посилання буде, але як «Discord Q-Hub», а не «вступай у CORE».
- **Ризики спільного сервера:**
  - гравці інших сімей потрапляють на сервер чужої сім'ї й бачать його канали;
  - внутрішні розмови сім'ї стають видимі стороннім, якщо запрошення веде на весь сервер;
  - правила QuantRP забороняють рекламувати сторонні ресурси без погодження з командою проєкту — у грі, не на сайті, але гравці можуть кидати запрошення в ігровий чат.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Гравець знаходить, де спитати (Priority: P1)

Гравець не знайшов відповіді в частих питаннях чи інструкції й натискає «Спитати в Discord». Він потрапляє одразу в канал Q-Hub на сервері CORE, де може поставити питання, і не бачить внутрішніх каналів сім'ї.

**Why this priority**: без цього питання губляться або йдуть в особисті повідомлення власнику.

**Independent Test**: новий акаунт Discord переходить за посиланням із сайту — потрапляє в канал Q-Hub і бачить лише канали для гостей Q-Hub.

**Acceptance Scenarios**:

1. **Given** будь-яке місце сайту чи програми, де пропонується «спитати», **When** гравець натискає посилання, **Then** відкривається запрошення на сервер CORE з першим каналом — каналом Q-Hub.
2. **Given** гравець приєднався за запрошенням Q-Hub, **Then** він бачить лише канали Q-Hub (питання, помилки, новини), а не канали сім'ї.
3. **Given** посилання ще не задано, **Then** кнопки «Discord» ніде немає (а не мертве посилання).

---

### User Story 2 - Одне посилання для всього сайту й програми (Priority: P1)

Адмін вписує посилання на Discord один раз — і воно з'являється в підвалі, на сторінці «Програма», в частих питаннях, в інструкції до мапи й у налаштуваннях програми. Запрошення прострочилося — адмін міняє його в одному місці без релізу.

**Why this priority**: запрошення Discord протухають або змінюються; п'ять копій посилання в коді — п'ять місць, які забудуть оновити.

**Independent Test**: адмін змінює посилання — за хвилину нове видно в підвалі, на «Програмі» й у програмі.

**Acceptance Scenarios**:

1. **Given** адмін, **When** він зберігає нове посилання, **Then** воно видне всюди, де є «Discord», без нового релізу.
2. **Given** гравець чи гість, **Then** змінити посилання неможливо (перевіряє база, SQL-тест дозволу й заборони).
3. **Given** посилання не на discord.gg / discord.com, **Then** збереження відхиляється.

---

### User Story 3 - Підпис CORE веде на сервер (Priority: P3)

У підвалі «by CORE» (033) стає посиланням на той самий Discord.

**Why this priority**: зручно, але не обов'язково; залежить від 033.

**Acceptance Scenarios**:

1. **Given** підвал сайту, **When** гравець натискає «CORE», **Then** відкривається те саме запрошення, що й «Discord».

---

### Edge Cases

- **Сервер сім'ї закрито чи перейменовано** — адмін прибирає посилання, кнопки зникають, нічого не ламається.
- **Запрошення має обмеження за часом чи кількістю** — потрібне безстрокове запрошення без ліміту; інакше кнопки ведуть на «запрошення недійсне».
- **Інструкція до мапи вже має своє поле Discord** — воно лишається для іншого посилання, якщо задане; якщо порожнє — береться загальне.
- **Гравець кидає запрошення в ігровий чат** — поза сайтом; сайт не просить цього робити.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Сайт і програма MUST мати одне посилання «Discord Q-Hub», яке задає адмін на сайті без релізу.
- **FR-002**: Посилання MUST показуватися в підвалі сайту, на сторінці «Програма» (блок «Знайшли помилку чи маєте ідею?»), у «не знайшов» частих питань і навчання, в інструкції до мапи (якщо там не задано свого) і в налаштуваннях програми.
- **FR-003**: Без посилання кнопки Discord MUST не показуватися.
- **FR-004**: Змінювати посилання MUST лише адмін; база перевіряє права (SQL-тест: адмін — так, `user` і гість — ні).
- **FR-005**: Посилання MUST бути запрошенням Discord (`https://discord.gg/…` або `https://discord.com/invite/…`).
- **FR-006**: Текст біля посилання MUST казати «Discord Q-Hub» / «Спитати в Discord», а не «вступай у сім'ю» (рішення 033, FR-004).
- **FR-007**: Програма MUST отримувати посилання з сайту й пам'ятати останнє, щоб показувати його без інтернету.

### Key Entities

- **Налаштування сайту**: посилання на Discord Q-Hub; хто й коли змінив. Пізніше сюди ж можна додати інші загальні посилання.

## Success Criteria *(mandatory)*

- **SC-001**: Посилання змінюється адміном і видне всюди за ≤ 1 хв без релізу.
- **SC-002**: Гравець, що перейшов за посиланням, бачить лише канали Q-Hub — 0 каналів сім'ї (перевірка новим акаунтом).
- **SC-003**: На сайті й у програмі 0 мертвих посилань на Discord.

## Assumptions

- **Сервер налаштовує власник у Discord, не код:**
  - окремий публічний канал Q-Hub (питання, помилки, новини);
  - роль «Гість Q-Hub», якій видно лише ці канали;
  - безстрокове запрошення, що веде в канал Q-Hub.

  Без цього сайт вестиме стороннього гравця на сервер сім'ї з видимими внутрішніми каналами.
- Погоджувати з командою QuantRP не потрібно, поки посилання — лише на сайті й у програмі, а не в грі.
- GitHub для звітів про помилки прибрано (рішення власника 2026-11-01): помилки й ідеї — лише в Discord Q-Hub. «Що нового в збірці» на «Програмі» показує журнал оновлень на самій сторінці, а не реліз на GitHub. Завантаження інсталятора лишається з GitHub Releases.
- Рішення 033 оновлюється: «CORE» може вести на той самий Discord (US3), але без закликів вступити.
