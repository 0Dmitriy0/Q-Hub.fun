# Research: 095 — правила з програми адміна

## R1. Хто кого блокує

- **Факт (24.11.2026)**: запит `GET /index.php?/forum/10-…/` з UA `Mozilla/5.0 Q-Hub rules sync`. З ПК власника відповідь `200`, 53 КБ, `Server: cloudflare`. З функції Supabase щодня з 14.11 відповідь `403` по всіх 3 джерелах.
- **Decision**: блокують адреси дата-центру. Читаємо з домашньої адреси адміна під тією ж справжньою назвою.
- **Rationale**: це не обхід: ми не прикидаємось браузером, не розв'язуємо перевірку й не міняємо адресу навмисно. Адміністрація форуму не заперечує (листування 10–24.11).
- **Alternatives considered**: проксі чи «браузерний» UA для функції — це обхід захисту, відхилено. Збирати з програм гравців — недовірені дані й масове читання, відхилено. Чекати на адмінів форуму — правила стоять уже 11 днів, відхилено як єдиний шлях (лишається паралельно).

## R2. Що надсилає програма: сирі сторінки чи розібрані теми

- **Факт**: сторінка розділу 53 КБ, знімок `rules.json` 1,76 МБ (60 тем, 3374 пункти). Сирих сторінок ~60 + розділи з пагінацією, тобто орієнтовно 5–15 МБ.
- **Decision**: програма обходить форум і розбирає теми спільним кодом (`crawl.ts` + `parse.ts`), а надсилає `{ fresh, errors, titles }`.
- **Rationale**: тіло менше в ~5 разів. Функція не обходить форум удруге, а розбір лишається тим самим кодом: модуль один, і він уже без залежностей середовища (Node 24 читає `.ts`, Vite збирає в CJS).
- **Alternatives considered**: сирі сторінки й розбір на сервері. Це «чистіше» за довірою, але велике тіло і два проходи (функція не знає наперед, які сторінки потрібні). Довіра однаково забезпечена роллю admin.

## R3. Як програма дізнається, що пора

- **Факт**: `rules.json.fetched` оновлюється навіть тоді, коли всі джерела дали помилку: функція завжди перезаписує знімок (24.11 10:42 при 403). Тож на `fetched` покладатися не можна.
- **Decision**: нова таблиця `rules_sync_runs` (кожна спроба: коли, звідки, хто, результат). Пора, якщо немає вдалої спроби за 24 год. Програма читає останню вдалу (`select … where ok order by at desc limit 1`, RLS дозволяє admin). Додатково локально в програмі є `rulesync.json`: остання власна спроба, щоб після відмови не пробувати знову раніше ніж за 24 год.
- **Також**: функція більше не перезаписує `rules.json`, коли всі джерела з помилкою. Знімок і `fetched` лишаються від останнього вдалого оновлення.
- **Alternatives considered**: RPC `rules_sync_due()`. Зайва функція в базі, проста вибірка робить те саме.

## R4. Запобіжник від гіршого знімка (FR-007)

- **Decision**: у `guard.ts` джерело без помилки, але з 0 тем, або з кількістю пунктів < 50 % від попереднього знімка, вважається помилкою з причиною «підозріло мало пунктів (N замість M) — знімок не змінено». Діє для обох шляхів.
- **Rationale**: зламана розмітка форуму чи сторінка-заглушка не повинні стерти правила всім гравцям.
- **Alternatives considered**: діяти лише для шляху з програми. Але той самий ризик є й на сервері.

## R5. Перевірка «я не робот»

- **Decision**: у `get` програми зупиняємось на будь-якій відповіді, крім `200`, а також на `200`, якщо сторінка не схожа на форум IPS (немає `ipsLayout`/`ipsType` чи `<title>` з назвою форуму) або має ознаки перевірки (`cf-mitigated`, `challenge-platform`, `Just a moment`). Перша така сторінка зупиняє весь запуск, нічого не надсилаємо.
- **Rationale**: FR-004. Частковий результат не публікуємо (US2 AS1).

## R6. Темп і фон

- **Decision**: пауза 1 с між сторінками (у функції 250 мс; програмі нікуди поспішати). Запит через глобальний `fetch` Node 24 у головному процесі, без вікон. Перша перевірка через 2 хв після старту програми (щоб не заважати запуску гри), далі щогодини.
- **Alternatives considered**: прихований `BrowserWindow`. Він виглядав би як браузер для Cloudflare, тобто обхід, відхилено.

## R7. Workflow

- **Decision**: функція повертає `last_ok: { at, via }` (остання вдала спроба). Крок workflow червоний, якщо всі джерела з помилкою **і** `last_ok` старший за 24 год або відсутній. Інакше тільки `::notice::` «оновлено з програми адміна о …».
